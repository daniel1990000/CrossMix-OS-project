# Actual desktop native counter observations

The frozen Soldier/bike scene uses the private state digest in `scene.json`, the pinned patched host engine, software OpenGL and a fresh process for each repeat. After a 10-second warmup, five independent 30-second pairs compare only `Graphics.InternalResolution` 1x versus 2x, with manual frameskip 0 and automatic frameskip disabled. This is a stationary host setting comparison, not a frontend, device or demanding-profile comparison. No numerical performance budget was registered before the candidate observations; results are descriptive, not preset acceptance.

`comparison.json` and `runs/` are generated through the existing `tools.gameplay_benchmark` validator/importer/comparator. `raw/` retains unchanged native websocket observations. A nominal [0,30) analysis window starts at the retained initial game-status acknowledgement. The observer loop starts a few Python instructions later; acquisition completion and process lifetime are recorded separately. Responses outside the common window are excluded rather than attributed to it. Sampling measures native point counters; it is not continuous frame accounting.

The first pair 4 overlapped three brief native failure probes. Both arms are retained under `excluded/` and replaced after every other emulator process and the soak ended. The replacement copies the original frozen INIs, asserts their hashes, verifies that the running executable has the expected digest, binds port 19362's listener to that PID and rejects any additional live PPSSPP process. Other repeats retain launch sequencing, binary/configuration identity and native game/version corroboration. An independent live process/socket snapshot supports original pair 4; the soak has its own live binding receipt. The earlier experiments were not all instrumented with a prelaunch socket record.

Native `fps.actual` is PPSSPP's approximate flip count since its prior update once elapsed time reaches 1 second; it is not divided by the precise update interval. Values 30 versus 31 and tiny differences between arms must not be presented as improvement. The vblank-rate ratio is normalized: 100×actual/target. Neither metric proves panel pacing or input latency.

The separate 1x stationary soak requested 1,800 seconds and exited normally. It overlaps independently recorded native gameplay and menu/settings validation on other displays. It is shared-host stability evidence, not isolated performance or paired demanding-profile endurance. `soak-resources.json` covers a separately identified 1,200-second segment beginning about six minutes into that soak. It is not attached as full-duration resource coverage. Sampled RSS/PSS/CPU do not infer gameplay FPS, audio, energy or a leak diagnosis.

`audio-inventory.json` checks closed native WAV headers, readable frames and nonzero PCM presence. Native recording precedes the game-volume gain; SDL playback was dummy. No listening review occurred. Audio faults, frame-time p95, load/input latency and battery energy remain null. Game/audio/screenshots/states are private; only metadata, original scripts and native counters are exported.

The test-only instance shim remaps only PPSSPP's instance shared-memory name to avoid unrelated stale counters, and makes optional discovery registration fail locally so the native debugger can serve its local observer without waiting for external registration. Both arms use the same shim. It is not a production change or device behavior. Exact harness sources and configuration identities are retained for review; they refer to this private workspace and must not be run blindly elsewhere.
