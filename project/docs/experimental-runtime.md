# Private view-only source route

The D01 software path now connects the original admission work to the actual
`ProcessSourceConfiguration`, initialized PyUI binding, `EmbeddedRunner`,
dispatcher and existing principal/resident boundary. The fixed production
selector and the fixed private selector both return `None` in the shipped
payload. A saved card setting, case report, signature or environment flag cannot
select private configuration or turn production qualification on.

This is a conditional software implementation, not a physical pilot. The owner
has confirmed author notification and permission for private noncommercial
work. The retained owner attestation can support a scoped source-use review;
it is not a claim that correspondence was independently inspected or that
commercial, SDK or all third-party distribution terms were cleared. Actual
card/internal-file backups, independent retained readback, physical restoration
rehearsal and observed TG5040 runtime readiness remain required. The device was
unavailable for this work. No device admission or activation was performed.

## Fixed reviewed inputs

`bridge.experimental_runtime.RuntimeCandidate` binds the independent build,
complete expected source/project files and installed runtime/import identities,
media identity, exact original-device firmware/filesystem, one case digest,
kernel boot ID and principal PID/start identity. The mandatory source and
original Python module inventory is checked at construction. Additional
interpreter, library and import identities must come from reviewed inputs,
rather than being copied from the same observed card to make it pass.

On the real route, all currently loaded Python modules and the interpreter
must map to the reviewed SD or `rootfs/...` identities. Live observations
compare actual hashes, media, model, firmware/filesystem and ownership with
those independent expectations. Actual `/proc` principal/start and boot checks
are separate. A changed input, unexpected import, staged command, lost owner,
unsafe power preference or failed observation blocks the case. The existing
`enableButtonWatchers=false` and spruce save/poweroff route remain required.

`prepare_private_session()` requires exact typed `SourceUseEvidenceReview` and
`RecoveryRuntimeReview` objects. Source review can distinguish retained actual
delivery from retained owner-attested permission. Recovery/runtime review must
refer to actual independently reviewed backup/readback/restore and original
device observations. Constructors do not authenticate those facts; trusted
reviewed code supplies them after examining their evidence. No report or JSON
deserializer creates the objects. The prerequisite digests participate in the
candidate identity.

The host factory is separate. `prepare_fixture_session()` requires an explicit
`HostFixtureReview`, refuses device paths/live observations and retains
synthetic provenance. The subprocess fixtures compare independently generated
expected test bytes with separate observed fixture files. They establish no
actual TG5040 readiness or permission.

## Existing owners and process composition

Private configuration is supplied through fixed reviewed source, with
`execution_environment="private-experimental"` and all four production gates
false. It carries a sealed typed session, not a callback/module name from data.
The host fixture uses `host-fixture` and cannot target `/mnt/SDCARD`.

Every process independently verifies the same candidate/case inputs. Its local
journal uses a separate private directory per role/PID, avoiding a race for one
output file. These independently constructed verifier objects do not grant
new cases. Only the original principal's existing authenticated `PrincipalLease`
reserves the case, once, before starting its one source subtree. The original
helper, Linux child subreaper and resident delegation process retain their
existing ownership roles.

The existing relay authenticates the boot/principal lifetime, helper lineage,
peer credentials, nonce, MAC and sequence before accepting fixed experimental
phase checks. The resident binds the exact source peer at startup. It retains
the candidate/case/helper/source identities and phase in the existing private
MAC-protected lease record. A copied card record or independently minted
source-side session cannot substitute for the live resident's decision.

The source's `startup` request occurs only after its already initialized
Display, Controller, source models and quiescence checks succeed. No second
display/input owner or project supervisor starts. The view-only route refuses
mutating resident operations. If a real baseline startup requires an operation
that this restricted route cannot admit, initialization remains unready and
the experiment is blocked. Host composition with synthetic no-mutator startup
does not prove the actual boot sequence works; qualify that exact startup scope
before a physical pilot.

## Actual view restrictions

`EmbeddedRunner` attaches to the existing renderer and input callbacks and
uses the existing initialized model provider. The backend is read-only. Its
settings facade reads in-memory view preferences without entering
`SettingsStore.get()` or recovery. It does not overwrite existing settings,
navigation or incomplete transaction files. Project health and evidence
records remain explicit writes.

The real dispatcher checks every method against the private read allowlist.
Read-only browse/query/history/favorites, search and status views are available.
Game/tool launches, advanced menus, favorite changes, settings/control/theme
writes, library refresh, Resume, support export, USB and power transitions are
refused before backend or adapter callbacks. No live mutator adapters or launch
bridge are installed. The existing source command-staging seam and principal
command path independently reject a staged launch under a view-only case.

Checks occur around presentation, existing input polling and dispatcher work.
Changing an initialized owner, leaving quiescence or a failed callback blocks
fallback. The actual model's Confirm and Favorite paths are tested, including
their generated dispatcher requests; tests do not merely call a standalone
policy helper.

## Cooperative exit and kernel closure

The principal observation policy binds the actual authenticated reservation's
return deadline. It does not independently add a new grace period. The source
requests `return-start` before any cleanup callback. The resident records
`return_requested` and shortens the authenticated return deadline to at most
five seconds from that request, without extending an existing earlier limit.
The principal's observation callback reads the current signed deadline, so an
early user return receives the same bounded observation as a timed return.

Source cleanup closes only its project renderer, clears the existing input
queue, completes paired restoration and checks the unchanged owners, idle state
and absent staged command. Local health updates finish before the final
authenticated `return` request. Only then can the resident mark the view
`released` and the existing initialized classic menu continue. `released` does
not assert that a real classic frame or physical input was observed.

After authenticated release, the helper continues its ordinary kernel-owned
wait. A timeout, renderer exception, failed restoration, missing resident,
surviving descendant or helper failure does not clear the lease/dirty state or
start a replacement UI. The helper retains descendants through real `ECHILD`.
Final source closure also requires a successful exit and the exact released
lease record. Process closure and real UI/recovery/save qualification remain
separate facts.

Checks can request exit and report a blocked observation. They cannot safely
interrupt a stuck SDL/input/write syscall or guarantee process termination.
Keep the separately reviewed operator recovery route available. No process-name
kill, forced clean-save claim or new power/input owner is introduced.

## Evidence and remaining qualification

Journals retain only fixed events, monotonic times and opaque identity digests.
Provenance is explicitly `host_fixture` or `private_experimental`; the latter
means in-process/operator observations, not a physical qualification pass.
Existing anchored-file, bounded-write, fsync and readback checks remain in
place. Actual independent-media retention/readback is still an operator task.

The focused tests cover typed prerequisites, missing imports, changed payload,
real model/dispatcher restrictions, preserved settings/transactions, existing
renderer/input ownership, early return and failure rejection. Separate parent
composition tests exercise the actual resident socket, source helper/source
processes, authenticated case reservation, return and kernel closure. Full host
certification and packaging records identify the exact tested revision.

Before any physical execution, review the exact private source composition and
fixed configuration, complete the actual D02/D03 reviews, qualify baseline
startup and rehearse the independent recovery route. Run the physical casebook
and retain raw results. Production profiles, native candidates, Resume and
distribution remain separate reviewed decisions; this implementation does not
promote them automatically.
